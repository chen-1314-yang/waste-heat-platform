## 1. 定位

一个**独立的新站**：

- 结构沿用老站（六个功能页签：计算 / 实时模拟 / 帕累托 / LCA / 工况库 / 方法）；
- 把路演之后新做的东西**全部加进去**；
- 与老站**没有任何文件或代码依赖**；
- 老站一个字节都不动。

---

## 2. 非目标（明确不做）

- 不做线性叙事、不做全屏翻页演示模式——那是 PPT 的活，已经取消。
- 不做用户账号、登录、后端数据库。
- 不重写决策内核（复用既有实现，已验证 Python 与 JS 对拍 11 场景 0 差异）。
- 不改动老站的任何文件，也不与老站共享目录。
- 不做多语言、SEO、埋点统计。

## 4. 新增页签的内容

### 4.1 外部证据

收录路演后四轮检索的成果，每条**必须带"适用边界"**（caveat），
没有边界的条目不允许入库。

| 条目 | 关键数值 | 适用边界 |
|---|---|---|
| 全球 ORC 装机数据库 | 953 台 / 3512.7 MW | 无热源温度、无效率；741 台工质缺失；含年份脏值 |
| EU28 工业过程与余热（TNO） | 267 行，含热量与温度 | 工艺级汇总，非单一工厂实测 |
| 中国国家标准 | 10 项现行 | 其中 GB/T 37819-2019、GB/T 40286-2021 直接对应本类系统 |
| 膨胀机效率图谱 | 膨胀比 50–80 四档 | 试验台/模型结果，超范围外推无效 |
| R245fa / R1233zd 冷凝传热数据 | 板式换热器实验 | 工质物性，非整机性能 |
| HeatScout 实测案例 | 9 个，含经济性 | 各案例自带出处链接 |
| EPFL-IEA ORC 热经济模型 | 34 kW 参考容量，甲苯 | 公开可共享；参数为该参考工况 |
| PyPSA 技术造价库 | ORC 1376 EUR/kW_el | 出处 Tartière & Astolfi 2017 |
| CIETO 温度区间 | 余热回收 90–1000 ℃ | 库自述工厂级数字为合成假设 |

### 4.2 校准工作台

每个校准项显示：内核现值 / 外部口径 / 差异分析 / 影响 / 状态。
**状态默认 `待定`，待定项不进入演示数值**——这样在拍板之前，
站上算出来的数字与已提交的申报书仍然一致。

首项：ORC 单位造价。内核用 91.5 kW 小机组固定单价（23800 元/kW）
代表全规模（100 kW–20 MW），属量纲不匹配；外部口径下单位造价随规模
从 12105 降至 5059 元/kW，隐含回收期由 5.6 年降至 1.2–2.9 年。

### 4.3 边界与口径

| 项目 | 口径 | 等级 |
|---|---|---|
| ORC 减碳量 | 仿真净功率 × 运行小时 × 电网因子 | 推算，非实测 |
| 供热减碳 | 替代天然气估算 | 演示估算 |
| 成本 / 回收期 | 代理模型 | 示意，非报价 |
| 工况库非公开案例 | 工程示例 | 示意 |
| TOPSIS 指标 | 典型演示值 | 待替换 |

### 4.4 演进记录

这个站自己的版本记录。每条写清"改了什么、有没有影响已提交材料的口径"。

## 5. 架构：一份源，两种产物

```
新站/
├── content/                  内容与数据（日常只改这里）
│   ├── site.json             站点元信息
│   ├── evidence.json         外部证据
│   ├── calibration.json      校准工作台
│   ├── boundaries.json       边界与口径
│   ├── changelog.json        演进记录
│   └── demo/                 决策平台数据（自老站复制一份）
├── src/
│   ├── styles/               样式（CSS 变量 + 组件样式）
│   ├── engine/               决策内核（自老站复制一份，独立演进）
│   └── views/                各页签渲染逻辑
├── build.py                  构建脚本
└── dist/
    ├── site/                 多文件站点
    └── 工业余热回收_新版_单文件.html
```

**内容与代码分离**：以后改文字、改数字、加条目都只动 `content/` 里的 JSON，
不用碰代码。这是"随进度不停改"的前提，也是避免"改排版把整页改崩"的办法。

**一份源出两种产物**：多文件版用于将来部署，单文件版用于本地打开与分享。
两版内容必然一致（老站现在这两版是分开维护的，有漂移风险）。

## 6. 关键约束

| 约束 | 来源 | 影响 |
|---|---|---|
| 零外部依赖、离线可用 | 老站已验证（0 个外链） | 不引 CDN，图表自绘，字体不下载 |
| 内容与代码分离 | "随进度不停改" | 内容全部数据驱动 |
| 与已提交材料不冲突 | 申报书/视频已提交 | 数字变更必须标注版本与日期；待定项不生效 |
| 独立、不碰老站 | 用户明确 | 不共享目录、不共享代码 |

## 7. 视觉

**沿用老站的视觉基底**（背景 `#F5F9FC`、主色 `#16324F`、强调 `#0E9F8A`、
数据色 蓝/金/红）——它已经与提交出去的材料一致，不必推翻。

如果以后想换成路演 PPT 的"水乡墨绿"，因为样式集中在 CSS 变量里，
**改一处即可全站生效**，不影响内容。

图表自绘 SVG / canvas。坐标轴范围按数据实况设定，避免出现
"几条线挤在一起看不出差别"（这是 PPT 阶段反复被指出的问题）。

---

## 8. 技术选型与理由

| 选择 | 理由 |
|---|---|
| 纯静态 HTML/CSS/JS，不用框架 | 单文件可分享、离线可用、无构建依赖 |
| 构建脚本用 Python | 本机已有 Python，与项目其他脚本一致 |
| 图表自绘 | 避免 CDN 依赖，也避免图表库默认样式与设计冲突 |
| 决策内核沿用既有纯函数实现 | 已验证，重写无收益 |

## 10. 风险

| 风险 | 应对 |
|---|---|
| 变成"没人维护的站点" | 内容与代码分离，改内容不动代码 |
| 与老站内容漂移 | 两站独立演进，演进记录各记各的；不设同步机制 |
| 校准数字与已提交材料冲突 | 默认标待定，不进入演示数值；变更需拍板 |
| 单文件体积过大 | 构建时压缩；数据按页签分块内联 |

---

## 11. 验收标准

1. 断网打开单文件版，十个页签全部可用。
2. 改 `content/` 中任一 JSON，重新构建后页面随之变化，**无需改代码**。
3. 计算页输入参数后即时出结果，数值与老站一致（待定校准项不生效）。
4. 外部证据每条都带适用边界；边界页完整列出各项口径等级。
5. 新站与老站**没有任何文件或代码依赖**；老站文件未被修改。
