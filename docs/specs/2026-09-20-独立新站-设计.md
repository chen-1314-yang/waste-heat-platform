# 工业余热回收项目 · 独立新站设计文档

日期：2026-09-20（v2 修订）
状态：待用户评审

---

## 0. 本次修订了什么

第一版设计把它定位成"老站的 v4，成熟后并入老站"。**这个定位是错的**，现修正为：

1. **独立新站**——与老站互不依赖、互不替换。老站原地不动。
2. **路演 PPT 不再制作**，展示职责交给本网站。

第 2 条带来一个实质变化：网站不能只是"工具面板"，它得**同时承担原来 PPT 的叙事职责**。
这是本次修订最大的设计改动。

---

## 1. 定位

一个**自成一体的项目展示站**，同时具备两种能力：

- **讲清楚**——能像 PPT 一样把项目从头讲到尾（背景 → 问题 → 方法 → 结果 → 影响）；
- **能上手**——随时可以进入决策平台亲自试，而不是只让观众看静态图。

它要能承担三种场合：

| 场合 | 需要的能力 |
|---|---|
| 站着讲（答辩/评审） | 全屏、键盘翻页、节奏可控、不被误触打断 |
| 坐着看（评委/老师自己浏览） | 滚动阅读、章节清晰、关键数字一眼可见 |
| 动手试（有人想验证） | 完整的决策平台交互，输入参数即时出结果 |

---

## 2. 非目标（明确不做）

- 不做用户账号、登录、后端数据库。
- 不重写决策内核。新站复用既有内核（已验证 Python 与 JS 对拍 11 场景 0 差异）。
- 不做多语言、SEO、埋点统计。
- **不改动老站的任何文件**，也不与老站共享代码或数据目录。
- 不做在线协作编辑。

---

## 3. 核心设计：叙事主线 + 工具模式

### 3.1 为什么不是"六个并列页签"

老站是六个并列页签的工具面板——**适合动手，不适合讲**。PPT 是线性叙事，适合讲但不
能动手。新站要把两者合起来，所以主线是**线性叙事**，交互嵌在叙事需要它的位置。

### 3.2 三层结构

| 层 | 形态 | 用途 |
|---|---|---|
| **叙事层**（主线） | 纵向滚动的章节，章节内可嵌入交互组件 | 默认进入的视图；替代 PPT |
| **演示层** | 全屏、键盘左右翻页、章节切片 | 站着讲的时候用；按 `P` 进入 |
| **工具层** | 完整的决策平台（输入参数 → 路径筛选 → 排序 → 减碳与收益） | 叙事中"我们的方法"那一章可直接试用；也可独立直达 |

三层共用同一份内容与同一个决策内核，**不存在"演示版和工具版数字不一致"的可能**。

### 3.3 叙事章节（草案，章节顺序即讲故事的顺序）

1. **封面**：项目名、团队名（成员名单预留空位）、一句话主张
2. **家底**：我国能源消耗总量、余热总量、经济可回收量、政策目标
3. **问题**：利用效率低 / 技术原理的局限 / 静态评价的局限
4. **一个真实的困境**：以具体企业为例，讲它现实中卡在哪
5. **我们的答案**：把经验决策变成数据决策（一句话说清）
6. **怎么做**：物性库仿真 → 代理模型 → 代理优化 → 指标评价的完整链路
7. **动手试**：嵌入决策平台，观众自己输入、自己看结果
8. **效果**：减碳量、经济性、交付的软件
9. **不是孤例**：外部证据（953 台全球装机、EU28 余热底数、10 项中国国家标准）
10. **边界与诚实**：哪些是实测、哪些是推算、哪些是示意
11. **演进与展望**：这个站自己的版本记录 + 下一步

第 9~11 章是相对 PPT 的**增量**——PPT 没来得及讲的东西，网站可以一直讲下去。

## 4. 架构：一份源，两种产物

```
新站/
├── content/                  内容与数据（日常只改这里）
│   ├── site.json             站点元信息：标题、团队、版本
│   ├── narrative.json        叙事章节的文字与图表配置
│   ├── evidence.json         外部证据层
│   ├── boundaries.json       诚实性边界
│   ├── changelog.json        演进日志
│   └── demo/                 决策平台数据（自老站迁移）
├── src/
│   ├── styles/               样式（CSS 变量 + 组件样式）
│   ├── engine/               决策内核（自老站移植，纯函数）
│   ├── views/                叙事层 / 演示层 / 工具层
│   └── app.js                装配与模式切换
├── build.py                  构建脚本
└── dist/
    ├── site/                 多文件站点
    └── 工业余热回收_单文件版.html
```

内容与代码分离：改文字、改数字、加章节都只动 `content/`，**不用碰代码**。
构建脚本一次产出多文件版与单文件版，两者内容必然一致。

## 5. 关键约束

| 约束 | 来源 | 影响 |
|---|---|---|
| 零外部依赖、离线可用 | 老站已验证（0 个外链） | 不引 CDN，图表自绘，字体不下载 |
| 内容与代码分离 | 用户要求"随进度不停改" | 内容全部数据驱动 |
| 与已提交材料不冲突 | 申报书/视频已提交 | 数字变更必须显式标注版本与日期 |
| 独立、不碰老站 | 用户本轮明确 | 不共享目录、不共享代码 |
| 视觉与路演 PPT 一致 | PPT 已定"水乡墨绿" | 沿用该基底，不再另立一套 |

## 6. 内容模型（要点）

### 6.1 narrative.json

```json
{
  "sections": [
    {
      "id": "problem",
      "title": "问题",
      "kind": "narrative",
      "blocks": [
        {"type": "text", "md": "..."},
        {"type": "stat", "items": [{"value": "...", "label": "...", "source": "..."}]},
        {"type": "chart", "chart": "problems", "note": "口径说明"}
      ]
    },
    {
      "id": "try-it",
      "title": "动手试",
      "kind": "tool",
      "component": "decision-platform"
    }
  ]
}
```

`kind` 只有三种：`narrative`（纯叙事）、`tool`（嵌入工具）、`evidence`（证据表）。
章节顺序由数组顺序决定，**改顺序不用改代码**。

### 6.2 evidence.json —— 外部证据层

每条**必须带 `caveat`**（适用边界），没有 caveat 的条目不允许入库。

计划收录：953 台装机库、EU28 工业过程与余热（TNO）、10 项中国国家标准、
膨胀机效率图谱、R245fa / R1233zd 冷凝传热数据、HeatScout 9 个实测案例、
EPFL-IEA ORC 热经济模型、PyPSA 造价库、CIETO 温度区间。

### 6.3 boundaries.json —— 诚实性边界

| 项目 | 口径 | 等级 |
|---|---|---|
| ORC 减碳量 | 仿真净功率 × 运行小时 × 电网因子 | 推算，非实测 |
| 供热减碳 | 替代天然气估算 | 演示估算 |
| 成本 / 回收期 | 代理模型 | 示意，非报价 |
| 工况库非公开案例 | 工程示例 | 示意 |
| TOPSIS 指标 | 典型演示值 | 待替换 |

### 6.4 changelog.json —— 演进日志

不再是"相对老站的差异"，而是**这个站自己的版本记录**。每个版本条目必须写清
"改了什么、有没有影响已提交材料的口径"。

## 7. 视觉方向

- **基底**：沿用路演 PPT 已定的"水乡墨绿"——墨绿主色 + 大量留白 + 克制的绿植感。
- **数据色**：墨绿基底上限定一组数据色（不超过 4 色），避免颜色过杂。
- **字体**：中文用思源宋体 / 微软雅黑体系，数字与英文用衬线数字体现科研感；
  不下载外部字体（保持离线）。
- **图表**：自绘 SVG / canvas；坐标轴范围按数据实况设定，避免"几条线挤在一起
  看不出差别"（这是 PPT 阶段反复被指出的问题）。
- **演示态**：大字号、高对比、暗背景，保证在投影仪上看清。

## 8. 技术选型与理由

| 选择 | 理由 |
|---|---|
| 纯静态 HTML/CSS/JS，不用框架 | 单文件可提交、离线可用、无构建依赖 |
| 构建脚本用 Python | 本机已有 Python，与项目其他脚本一致 |
| 图表自绘 | 避免 CDN 依赖，也避免图表库默认样式与设计冲突 |
| 决策内核沿用既有纯函数实现 | 已验证，重写无收益 |

## 9. 部署（未定，且当前有阻塞）

本设计**不依赖部署**：dist 产物先满足"本地打开 + 单文件分享"两个用途。

要放到线上并持续更新，需要一个**能写入的** GitHub 令牌（现有的 codex-search 是
公开仓库只读，建不了仓库也传不了文件）。三条备选路径稍后再定。

---

## 10. 风险

| 风险 | 应对 |
|---|---|
| 变成"没人维护的站点" | 内容与代码分离，改内容不动代码 |
| 叙事与工具数字不一致 | 三层共用同一份内容与同一内核 |
| 视觉重蹈 PPT 阶段反复 | 沿用已定"水乡墨绿"，不重新选色 |
| 单文件体积过大 | 构建时压缩；数据按章节分块内联 |
| 与已提交材料口径冲突 | 数字变更必须标注版本与日期；边界页集中说明 |

---

## 11. 验收标准

1. 断网打开单文件版，叙事、演示、工具三层全部可用。
2. 改 `content/` 中任一 JSON，重新构建后页面随之变化，**无需改代码**。
3. 按 `P` 进入演示态，可用键盘完整走完全部章节，投影仪上字够大。
4. 工具层输入参数后即时出结果，且数值与老站一致。
5. 证据层每条都带适用边界说明；边界页完整列出各项口径等级。
6. 站点与老站**没有任何文件或代码依赖**。
